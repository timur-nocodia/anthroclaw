# v1.3.0 Runtime Product Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship AnthroClaw v1.3.0 as the first post-migration product hardening release on top of the Pi-native Runtime v1 harness.

**Architecture:** Keep Runtime v1/Pi as the product baseline and improve six operator-facing subsystems without reintroducing Claude Agent SDK semantics. Each subsystem must expose a durable backend contract, focused tests, and dashboard/API visibility where useful. All live side effects remain gateway-bound and operator-auditable.

**Tech Stack:** TypeScript, Vitest, Next.js App Router, SQLite/better-sqlite3 where durability already exists, YAML config writer, existing Gateway/Agent tool contracts, existing metrics/diagnostics/fleet APIs.

---

## Release Scope

v1.3.0 includes:

- `manage_cron` v2 runtime primitive cleanup.
- Peer-isolated memory for `public` agents.
- Persistent approval queue.
- WhatsApp approval UX/capability contract.
- Richer observability for runtime, tools, memory, approvals, cron, and deploys.
- Deploy/fleet polish for staged rollout and operator confidence.

v1.3.0 explicitly excludes:

- Returning to Claude Agent SDK as the primary harness.
- Private named-agent rollout work as release criteria.
- Live destructive actions without explicit durable approval records.
- A full enterprise multi-tenant admin model.

## Files And Responsibilities

- `src/agent/tools/manage-cron.ts`  
  Own the model-visible `manage_cron` v2 schema. The schema must accept `action`, `id`, `schedule`, `prompt`, `run_once`, `expires_at`, and `enabled`; it must not accept user-controlled `deliver_to`.

- `src/cron/dynamic-store.ts`  
  Own durable cron job shape, migrations from old job records, and persistence of `createdBy`, `delivery`, `durable`, `expiresAt`, and audit timestamps.

- `src/cron/scheduler.ts` and `src/cron/delivery-contract.ts`  
  Own execution semantics for durable/one-shot/expired jobs and stable delivery context checks.

- `test/agent/tools/manage-cron.test.ts`, `test/cron/dynamic-store.test.ts`, `test/cron/delivery-contract.test.ts`, `test/cron/scheduler.test.ts`  
  Own regression tests for the v2 cron contract.

- `src/memory/store.ts`, `src/memory/search.ts`, `src/memory/provider.ts`, `src/agent/tools/memory-search.ts`, `src/agent/tools/memory-write.ts`, `src/agent/agent.ts`, `src/gateway.ts`  
  Own peer-scoped memory context for public agents while keeping private/trusted behavior unchanged.

- `test/memory/store.test.ts`, `test/memory/search.test.ts`, `test/agent/tools/memory-search.test.ts`, `test/agent/tools/memory-write.test.ts`, `src/__tests__/capability-cutoff-e2e.test.ts`  
  Own peer-isolation tests and public-profile leak prevention.

- `src/security/approval-broker.ts`  
  Move approval requests from process-only memory to a durable queue interface while preserving the existing `request()` / `resolveBySender()` API.

- `src/security/approval-store.ts`  
  New durable approval store. Use JSON or SQLite only if the repo already has a stronger adjacent pattern; default to a small JSON store matching `DynamicCronStore` unless tests show concurrency risk.

- `src/security/__tests__/approval-broker.test.ts`, `test/gateway-approval-callback.test.ts`, `src/channels/__tests__/telegram-approval.test.ts`  
  Own persistence, restart, sender-authenticated resolution, expiration, and replay prevention.

- `src/channels/types.ts`, `src/channels/telegram.ts`, `src/channels/whatsapp.ts`, `src/channels/whatsapp-classifier.ts`  
  Own channel capability contracts and WhatsApp approval fallback UX.

- `src/channels/__tests__/whatsapp*.test.ts`, `test/channels/whatsapp.test.ts`, `src/channels/__tests__/telegram-approval.test.ts`  
  Own WhatsApp text-code approval behavior and channel-specific capability tests.

- `src/metrics/store.ts`, `src/metrics/collector.ts`, `src/metrics/insights.ts`, `src/diagnostics/bundle.ts`, `ui/app/api/metrics/route.ts`, `ui/app/(dashboard)/fleet/[serverId]/logs/page.tsx`, `ui/app/(dashboard)/fleet/[serverId]/runtime/page.tsx`
